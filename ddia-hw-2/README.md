# HW2: стратегии устойчивости

Go 1.26.1+, внешних зависимостей нет. Запуск тестов из этой папки: `./test.sh`.

`Sender.Send(ctx)` выполняет подзапрос и поддерживает отмену через `ctx.Done()`.
`Client.Do` принимает Sender и Budget, `MultiClient.Do` — список Sender и Budget.
Каждый Sender относится к одному логическому запросу и обслуживает его попытки.

`MaxRequests` включает первую попытку. `FastErrors`, `Failures`, `Timeouts` —
число ошибок соответствующего типа, после которых ещё разрешён повтор;
ноль запрещает повтор после такой ошибки. `Latency` ограничивает весь запрос,
`SubrequestLatency` — одну попытку. Задержки входят в общий бюджет.
Вложенные стратегии используют общий бюджет через контекст запроса.

`Default` делает одну попытку. `Retries` повторяет 4xx/5xx/timeout.
`Backoff` удваивает задержку только после 5xx/timeout.
В `RoundRobin.Strategy` и `CircuitBreaker.Strategy` можно передать `Backoff`;
по умолчанию используется `Default`.
Каждая попытка вложенной стратегии выбирает следующий доступный узел.

`Hedging` запускает первый узел сразу, остальные одновременно через `Delay`.
Побеждает первый 2xx, остальные отменяются.
Здесь учитывается только общий `Latency`; при отсутствии успеха ожидается его истечение.

Circuit breaker исключает узел на `Cooldown`, когда в полном окне `Window`
доля ошибок превышает `ErrorThreshold`. После паузы окно очищается.
Если исключены все узлы, клиент ждёт ближайшего возврата в пределах общего бюджета.
Состояние ротации и circuit breaker принадлежит одному логическому запросу.
